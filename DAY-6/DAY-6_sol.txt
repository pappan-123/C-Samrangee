# COMPUTER CODES & ENCODING SCHEMES – MCQs with Proper Explanation & Examples

---

## 1. Which of the following is a non-weighted, self-complementing code?

**Answer:** **B) Excess-3**

### Explanation:

* **Excess-3** is a **non-weighted code** because bit positions do not have fixed weights.
* It is also **self-complementing**, meaning:

  * Taking the 1’s complement gives the 9’s complement of the decimal number.

### Example:

Decimal **2** in Excess-3:

* 2 + 3 = 5
* 5 in binary = **0101**

1’s complement of 0101:

* 1010

1010 in Excess-3:

* Binary 1010 = Decimal 10
* 10 − 3 = 7

7 is the **9’s complement of 2**.

---

## 2. The decimal number 14 is represented in BCD (8421) as:

**Answer:** **B) 0001 0100**

### Explanation:

BCD stores each decimal digit separately in 4 bits.

* Decimal 1 → 0001
* Decimal 4 → 0100

So:
14 = **0001 0100**

### Example:

Decimal 27 in BCD:

* 2 → 0010
* 7 → 0111

Result:
**0010 0111**

---

## 3. How many invalid bit patterns exist in the 4-bit Binary Coded Decimal (8421) scheme?

**Answer:** **B) 6**

### Explanation:

4 bits can represent:
2^4 = 16

But BCD only uses decimal digits:
0 to 9 → 10 combinations.

Invalid combinations:
16 − 10 = **6**

### Invalid BCD codes:

1010, 1011, 1100, 1101, 1110, 1111

---

## 4. Which code is specifically designed to minimize errors in mechanical systems where multiple bits might change at once?

**Answer:** **C) Gray Code**

### Explanation:

In Gray code, only **one bit changes at a time**.

This reduces errors in:

* Shaft encoders
* Mechanical switches
* Position sensors

### Example:

Binary counting:

* 0111 → 1000
  (4 bits change)

Gray counting:

* 0100 → 1100
  (Only 1 bit changes)

---

## 5. What is the 84-2-1 representation of the decimal digit 5?

**Answer:** **B) 1011**

### Explanation:

Weights are:
8, 4, −2, −1

For 1011:
1(8)+0(4)+1(-2)+1(-1)=8-2-1=5

So decimal 5 = **1011**

---

## 6. In Gray to Binary conversion, the second bit of the binary sequence is found by:

**Answer:** **A) XORing the first binary bit with the second gray bit**

### Rule:

* First Binary bit = First Gray bit
* Next Binary bit:
  B_n = B_{n-1} \oplus G_n

### Example:

Gray = 1011

* B1 = 1
* B2 = 1 XOR 0 = 1
* B3 = 1 XOR 1 = 0
* B4 = 0 XOR 1 = 1

Binary = **1101**

## 7. To convert a BCD digit to Excess-3, we add:

**Answer:** **C) 0011**

### Explanation:

Excess-3 means adding decimal 3.

### Example:

BCD of 4:

* 0100

Add 0011:
0100 + 0011 = 0111

So Excess-3 of 4 = **0111**

## 8. When adding two Excess-3 numbers, if no carry is generated from the addition of two nibbles, what is the correction factor?

**Answer:** **B) Subtract 0011**

### Explanation:

In Excess-3 arithmetic:

* Carry generated → add 0011
* No carry → subtract 0011

### Example:

Suppose result without carry:
1001

Correction:
1001 - 0011 = 0110

## 16. Which of the following is NOT a weighted code?

**Answer:** **C) Gray Code**

### Explanation:

Weighted codes assign positional weights.

Examples:

* 8421
* 2421
* 84-2-1

Gray code does not use positional weights.

### Example:

Gray sequence:
000 → 001 → 011 → 010

No weights involved.

In **Excess-3 (XS-3)** code, each decimal digit is represented by adding **3** to the digit and then converting to binary.

Steps:

1. Convert each decimal digit to XS-3.
2. Add the binary numbers.
3. If carry occurs → add `0011` to the lower nibble.
   If no carry → subtract `0011`.
4. Convert result back to decimal and BCD.

---

# 1) (8 + 9)

### Step 1: XS-3 codes

* (8 \rightarrow 8+3=11 \rightarrow 1011)
* (9 \rightarrow 9+3=12 \rightarrow 1100)

### Step 2: Add

```text
  1011
+ 1100
-------
10111
```

Carry generated.

Lower 4 bits = `0111`

Add `0011` correction:

```text
0111
0011
-----
1010
```

Final result:

```text
0001 1010
```

### Step 3: Decode

* `0001` → 1
* `1010` → 7

So decimal sum = **17**

### BCD of 17

```text
0001 0111
```
